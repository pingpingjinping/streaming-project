# 작품 연결 수정

관리자는 작품 상세의 **작품 연결**에서 제목 또는 ID로 상대 작품을 검색하고
**이 작품으로 변경**을 눌러 연결을 지정한다. Anissia 상세에서는 ReAnime 영상
작품을, ReAnime 상세에서는 Anissia 자막 작품을 선택한다. 검색 결과는 원제,
연도, 형식, ID를 함께 표시한다. **자동 매칭으로 되돌리기**는 수동 지정만 지운다.

연결은 모든 사용자에게 적용된다. 읽기는 로그인 사용자, 변경·복귀는 관리자만
가능하다. 수동 연결은 가져온 `anime_reanime_matches`와 검토·자막 레지스트리를
수정하지 않고 별도의 `anime_work_match_overrides`에 저장한다. 따라서 DB 갱신이
수동 지정을 덮어쓰지 않는다. 두 ID는 각각 유일하며 다른 수동 지정과 충돌하면
기존 연결을 유지하고 409를 반환한다.

수동 지정은 영상 재생, Anissia 포스터, ReAnime→Anissia 자막 ID, 연결된 작품
목록에 우선 적용된다. 양쪽 ID를 점유했던 기존 자동 연결은 제외한다. 저장·복귀
시 해당 영상 검색 캐시를 비운다. 확정한 ReAnime 작품에 요청 회차가 없으면
다른 ReAnime 검색 후보로 조용히 바꾸지 않는다. 다른 영상 제공처와 사용자의
회차 설정은 기존 방식으로 동작한다.

등록하려는 두 작품은 가져온 카탈로그에 있어야 한다. 이 기능은 작품 단위
연결이며 회차별 직접 링크, 자막 파일 선택, 시즌 시작 회차 설정과 별개다.

검증: `npm run test:subtitles`, `npm run build`.
`REVIEWED_TEST_DATABASE_URL`이 있으면 실제 Postgres로 마이그레이션, 충돌 롤백,
수동 지정 유지, 연결 목록, 복귀를 확인한다.

## 후보 연결

확정된 수동·검토·자동 연결을 먼저 예약하고, 남은 월간 후보를 전체적으로 배정한다.
작품 수를 먼저 최대화하고 같은 연결 수에서는 근거 점수 합을 최대화한다. 이미
선택한 후보도 다른 작품의 연결을 막으면 재배정한다. 검증된 AniList 작품의 여러
영상 URL은 한 작품으로 취급하며 동점은 안정된 ID 순서로 고른다.

후보는 확정 테이블에 쓰지 않는다. 가져온 후보와 현재 수동 연결에서 매번 계산하므로
확정·변경 직후 다른 후보의 예약도 반영한다. 시즌·파트·형식·화수 충돌과 역사적
검토 예약은 배정에서 제외한다. 연도 차이는 감점한 후보로 남을 수 있다. 번호가
명시된 후속 시즌을 번호 없는 대상에 배정하려면 같은 연도와 전체 원제 일치가
필요하다. 예전 `season_missing` 근거는 V4 카탈로그를 다시 가져오기 전까지 보류한다.

Anissia 영상 재생과 ReAnime 자막 ID가 같은 후보 배정을 사용한다. 후보 대상에
해당 화가 없으면 다른 ReAnime 작품을 조용히 검색하지 않는다. 다른 작품의 확정·후보
대상은 기존 제목 검색과 캐시에서도 제외한다. 상세의 작품 연결, 회차 목록, 재생
화면에 **후보 연결 · 대상 작품명 · 이유**를 표시한다. DB 연결 목록에서는 후보가
먼저 나오며 관리자에게 **이 후보로 확정**과 다른 작품 검색을 제공한다.

2025 50개 표본은 46개 확정 + 4개 후보 연결, 2026 50개는 44개 확정 + 6개 후보,
추가 50개는 21개 확정 + 28개 후보 + 1개 보류다. 남은 보류는 후속 시즌이
번호 없는 원작으로 연결되는 것을 막은 사례다. 이는 고정 표본의 신규 수집 재생
결과이며 운영 DB 연결률·정확도나 영상 재생 성공률은 아니다.
